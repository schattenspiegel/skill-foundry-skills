# V1-to-v2 grounding

Before migration:

1. Confirm the installed/deployed major versions and compatibility window.
2. Read the current official migration guide for every used feature.
3. Inventory models, validators, configuration, ORM/object loading, schema generation, serialization, and custom types.
4. Add behavior tests before changing APIs.
5. Migrate one behavior family at a time and remove deprecation warnings.

Common anchors in v2 include `model_validate`, `model_dump`, `ConfigDict`, `field_validator`, `model_validator`, and `TypeAdapter`, but names alone do not prove semantic equivalence. Check optional fields, aliases, serialization, custom validators, equality, dataclasses, generics, and ORM-style attribute loading where used.

## Migration routing

| V1 shape | V2 investigation |
|---|---|
| `parse_obj`, `parse_raw` | choose `model_validate` or `model_validate_json` from the actual input |
| `.dict()`, `.json()` | choose `model_dump` mode or `model_dump_json` from the consumer |
| `@validator`, `@root_validator` | select field/model validator and its before/after/wrap mode from semantics |
| `class Config` | translate each setting to `ConfigDict`; do not copy removed names |
| `orm_mode` / `from_orm` | test `from_attributes` against real objects and lazy attributes |
| `parse_obj_as`, root wrapper model | inspect `TypeAdapter` or `RootModel` based on desired output |
| `BaseSettings` from `pydantic` | move to separately versioned `pydantic-settings` |

Run pre-migration behavior tests under v1, then post-migration tests under v2.
Deprecation-free import/compilation is necessary but does not prove equivalent
conversion, requiredness, equality, or wire output.
